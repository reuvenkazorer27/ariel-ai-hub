Power BI MCP בלי Node.js

שרת ה‑MCP של מיקרוסופט למודלים סמנטיים נארז כקובץ הרצה מקומפל. Node נדרש רק למסלול ה‑NPX - אפשר לעקוף אותו לגמרי בהורדה ידנית של החבילה. המדריך מכסה את שרשרת העבודה המלאה: התקנת השרת, חיבורו ל‑Claude, הוספת הסקילים של Power BI, ועבודה שוטפת מול קובץ PBIP.

למה בלי Node חלק א׳ · התקנה חלק ב׳ · סקילים חלק ג׳ · עבודה שוטפת

למה זה עובד בלי Node

התיעוד הרשמי פותח ב‑npx, ומשם קל להסיק ש‑Node הוא תנאי סף. הוא לא. חבילת ה‑NPX רק מורידה ומריצה בינארי מוכן - ואת אותו בינארי אפשר להשיג ישירות מה‑Marketplace. הוא .exe עצמאי שמדבר stdio מול לקוח ה‑MCP.

מה שנדרש בפועל

Power BI Desktop מותקן, וקובץ פתוח בו. זהו. שרת ה‑MCP מתחבר למופע ה‑Analysis Services שרץ מתחת ל‑Desktop.

אפס הרשאות אדמין

כל מה שמתואר במדריך הזה - ההורדה, החילוץ, עריכת קובץ הקונפיגורציה, שכפול המאגר והוספת הסקילים - מתבצע בתוך תיקיית המשתמש ואינו דורש הרשאות מנהל. זו בדיוק הסיבה להימנע מ‑Node: התקנת Node דרך winget או המתקין הרשמי היא הצעד היחיד בשרשרת שכן היה דורש אדמין.

חלק א׳

התקנת שרת ה‑MCP

זהו התנאי המקדים לכל השאר. קודם מתקינים ורושמים את שרת ה‑MCP - רק אחר כך מוסיפים את הסקילים ומתחילים לעבוד. סקיל שמנסה לפנות לשרת שלא רשום ייכשל בשקט.

  1. הדבק את הכתובת בדפדפן

    אין כאן שום סקריפט ואין דף הורדות. מדביקים כתובת אחת בשורת הכתובת של הדפדפן, מקישים Enter, וההורדה מתחילה אוטומטית.

    זו הכתובת להעתקה - הפורמט המתאים, גרסה 0.1.9 לפלטפורמת win32-x64:

    https://marketplace.visualstudio.com/_apis/public/gallery/publishers/analysis-services/vsextensions/powerbi-modeling-mcp/0.1.9/vspackage?targetPlatform=win32-x64

    המבנה הכללי, למי שרוצה גרסה או פלטפורמה אחרות - מחליפים רק את שני הערכים בסוגריים:

    https://marketplace.visualstudio.com/_apis/public/gallery/publishers
/analysis-services/vsextensions/powerbi-modeling-mcp/[version]
/vspackage?targetPlatform=[platform]

    הקובץ נוחת בתיקיית ההורדות בשם ארוך שמסתיים ב‑.vsix.

  2. שנה את שם הקובץ בתיקייה - סיומת .zip

    קובץ VSIX הוא ארכיון ZIP רגיל עם סיומת אחרת. בתיקיית ההורדות: לחיצה ימנית על הקובץ ← Rename ← החלף את הסיומת .vsix ב‑.zip. Windows ישאל אם אתה בטוח - אשר.

    לא רואה סיומות? ב‑Explorer: לשונית View ← סמן File name extensions.

  3. חלץ ידנית לתיקייה לבחירתך

    לחיצה ימנית על ה‑ZIP ← Extract All ← בחר יעד, למשל:

    C:\MCPServers\PowerBIModelingMCP

    בלי סקריפט ובלי כלי חיצוני - החילוץ המובנה של Windows מספיק.

  4. הרץ פעם אחת לאימות

    הפעל את קובץ ההרצה שחולץ:

    C:\MCPServers\PowerBIModelingMCP\extension\server\powerbi-modeling-mcp.exe

    הרצה ללא ארגומנטים מדפיסה לקונסולה את בלוק ה‑JSON לרישום. אם הבלוק מודפס - הבינארי תקין ומוכן.

    שים לב לרובד extension\ בתוך הנתיב. הוא קיים בדיוק כי חילצנו את ה‑VSIX ידנית, וה‑ZIP עצמו מכיל תיקיית extension בשורשו.

  5. טען את ה‑JSON לתוך הקונפיגורציה של Claude

    העתק את הבלוק שהודפס בקונסולה. ב‑Claude, פתח את קובץ הקונפיגורציה דרך המסלול הזה:

    Customize ← Developer ← Edit Config

    הקובץ ייפתח בעורך טקסט. הוסף לתוכו את הבלוק ושמור.

    זה אותו קובץ שיושב ב‑%APPDATA%\Claude\claude_desktop_config.json - פשוט בלי לחפש אותו ידנית.

מלכודת העטיפה

קטע ה‑JSON בתיעוד הרשמי מתחיל ישירות ב‑"powerbi-modeling-mcp" בלי מפתח עוטף. הלקוחות דורשים mcpServers סביבו. הדבקה של הקטע כמו שהוא תיטען בלי שגיאה ובלי כלים - וזו התקלה הכי קשה לאבחון בכל התהליך.

כך זה צריך להיראות בפועל:

{
  "mcpServers": {
    "powerbi-modeling-mcp": {
      "type": "stdio",
      "command": "C:\\MCPServers\\PowerBIModelingMCP\\extension\\server\\powerbi-modeling-mcp.exe",
      "args": ["--start"],
      "env": {}
    }
  }
}

החלף את הנתיב בנתיב האמיתי אצלך - זה שהרצת בשלב 4.

סגור את Claude לגמרי - כולל במנהל המשימות

Claude קורא את קובץ הקונפיגורציה רק בעליית התהליך. סגירת החלון אינה סוגרת את התהליך: Claude Desktop ממשיך לרוץ ברקע, ולכן העריכה שביצעת פשוט לא תיטען, והכלים לא יופיעו.

  1. סגור את חלון היישום.
  2. פתח את מנהל המשימות (Ctrl+Shift+Esc), חפש את כל התהליכים בשם Claude, וסיים כל אחד מהם ב‑End task.
  3. פתח את Claude מחדש.

מי שמעדיף פקודה אחת במקום מנהל המשימות:

Get-Process Claude -ErrorAction SilentlyContinue | Stop-Process -Force

ב‑Claude Code בטרמינל - יציאה מהסשן והרצה מחדש מספיקה.

חלק ב׳

הוספת הסקילים של Power BI

שרת ה‑MCP נותן את הכלים. הסקילים נותנים את הידע - איך לבנות דוח PBIR תקין, איך לתכנן מודל סמנטי, מה הכללים של כל פורמט. מיקרוסופט מפרסמת אותם במאגר פתוח.

מה השתנה במאגר

ארבע סקילי הדוח הנפרדים (planning, design, authoring, management) אוחדו לסקיל אחד: powerbi-report-cli. הוא בוחר לבד את המצב המתאים לפי הבקשה. השמות הישנים כבר לא קיימים במאגר, אז מי שהתקין לפי הגרסה הקודמת של המדריך - פשוט מריץ שוב את שני השלבים הבאים. הסקריפט גם מוחק את הסקילים הישנים.

  1. שכפל או עדכן את המאגר

    המאגר הוא microsoft/skills-for-fabric. שכפול לתיקייה זמנית - לא לתיקיית העבודה. אם כבר שכפלת בעבר, אותה פקודה מושכת את העדכונים:

    $repo = "$env:TEMP\skills-for-fabric"
if (Test-Path "$repo\.git") {
  git -C $repo pull --ff-only
} else {
  git clone --depth 1 https://github.com/microsoft/skills-for-fabric.git $repo
}

    אין git? הורד ZIP מכפתור Code בדף המאגר וחלץ אותו כך שהתיקייה תהיה %TEMP%\skills-for-fabric.

  2. העתק רק את שני הסקילים של Power BI

    המאגר מכיל עשרות סקילים לכל שירותי Fabric - Spark, Eventstream, מיגרציות ועוד. רובם לא רלוונטיים, וכל סקיל מיותר גוזל הקשר ומבלבל את המודל בבחירה. לוקחים רק את שני הסקילים של Power BI, ואת שלושת קבצי הרקע המשותפים ש‑semantic-model-authoring מפנה אליהם (הם יושבים בתיקיית common של המאגר):

    $repo = "$env:TEMP\skills-for-fabric"
$dest = ".\.claude"                 # מתוך תיקיית הפרויקט שלך

# remove the four report skills from the old layout, if present
"powerbi-report-planning","powerbi-report-design",
"powerbi-report-authoring","powerbi-report-management" | ForEach-Object {
  Remove-Item "$dest\skills\$_" -Recurse -Force -ErrorAction SilentlyContinue
}

# the two Power BI skills
New-Item -ItemType Directory -Force -Path "$dest\skills" | Out-Null
foreach ($s in "semantic-model-authoring","powerbi-report-cli") {
  Copy-Item "$repo\skills\$s" "$dest\skills" -Recurse -Force
}

# shared files the model skill links to (../../common from inside the skill)
New-Item -ItemType Directory -Force -Path "$dest\common" | Out-Null
foreach ($f in "COMMON-CLI.md","COMMON-CORE.md","ITEM-DEFINITIONS-CORE.md") {
  Copy-Item "$repo\common\$f" "$dest\common" -Force
}

Get-ChildItem "$dest\skills" -Directory | Select-Object -ExpandProperty Name

    בסוף הריצה הרשימה צריכה להציג את semantic-model-authoring ואת powerbi-report-cli.

    סקיללמה הוא אחראי
    semantic-model-authoringטבלאות, עמודות, מדדים, קשרים, פרמטרי שדות, DAX ו‑TMDL
    powerbi-report-cliכל מחזור החיים של הדוח, בארבעה מצבים: תכנון ואישור מפרט, עיצוב (ויזואלים, פריסה, צבע, טיפוגרפיה), כתיבת קבצי PBIR, והעלאה והורדה מול Fabric

  3. הוסף קובץ MD שמחייב שימוש בסקילים

    Claude לא תמיד טורח לטעון סקיל מיוזמתו - הוא עלול לנחש תשובה ולערוך JSON ידנית במקום. קובץ CLAUDE.md בשורש תיקיית העבודה נטען אוטומטית בכל סשן והופך את זה לכלל מחייב:

    # Power BI workspace rules

## Skills are mandatory, not optional

Before ANY Power BI work, load the matching skill first.
Never edit model or report files from memory.

| Task | Skill to load first |
|---|---|
| Tables, columns, measures, relationships, DAX, TMDL | semantic-model-authoring |
| Planning a new report end to end | powerbi-report-cli (planning mode) |
| Visual selection, layout, colors, theme | powerbi-report-cli (design mode) |
| Writing or editing PBIR files | powerbi-report-cli (authoring mode) |
| Upload / download to Fabric | powerbi-report-cli (management mode) |

Rules:
- Announce which skill and mode you loaded before the first edit.
- If no skill fits, say so instead of improvising.
- The powerbi-modeling-mcp server must be connected before
  touching a live model. Verify with a local-instance listing.
- Do not close and reopen the PBIP file after edits.
  Use "Apply external changes" in Power BI Desktop instead.
- The powerbi-report-author and powerbi-desktop CLIs are NOT
  installed here (no Node.js). Skip their validate, preview and
  screenshot steps. Do not try to install them. After each batch
  of edits, ask me to apply the changes in Desktop and send a
  screenshot.

## RTL and Hebrew - non-negotiable

This report is Hebrew. RTL is not a finishing touch, it is a
requirement on every object you create or edit.

- Every page and every visual must be right-to-left.
- All titles are Hebrew, right-aligned, and read right-to-left.
- Axis labels, legends, tooltips, card labels, slicer headers
  and table/matrix headers: Hebrew, right-aligned.
- Column and measure display names are Hebrew.
- Numbers, dates, percentages and English measure names stay
  LTR inside the RTL layout. Do not mirror them.
- Never leave a default English title on a visual.
- After every batch of edits, re-check the newest visuals for
  leftover left-aligned titles. This is the most common miss.

DAX note: VAR identifiers must be English. A Hebrew VAR name
fails with "Invalid token" and silently returns an empty column,
with no visible error in the UI.

    שמור בשם CLAUDE.md בשורש התיקייה - לצד תיקיית .claude.

סקיל הדוח לא יעבוד במלואו בלי Node

powerbi-report-cli נשען על שני כלי CLI שמופצים כחבילות npm ודורשים Node - powerbi-report-author לאימות סכימת PBIR, להכנת חבילות העלאה ל‑Fabric ולתצוגה מקדימה, ו‑powerbi-desktop ללולאת הצילום והרינדור. בלי Node עדיין מקבלים את כל הידע של הסקיל ואפשר לערוך PBIR, אבל בלי אימות סכימה, בלי צילום מסך אוטומטי, ובלי מצב ההעלאה ל‑Fabric. לכן השורה על ה‑CLI בקובץ CLAUDE.md שלמעלה חשובה: בלעדיה Claude ינסה להתקין אותם.

semantic-model-authoring עובד במלואו בלי Node. וכל מה שתואר עד כאן במדריך לא דורש הרשאות אדמין.

ומי שיש לו Node?

המאגר מציע גם התקנה כפלאגין: /plugin marketplace add microsoft/skills-for-fabric ואז /plugin install powerbi-authoring@fabric-collection. הפלאגין מתקין את שני הסקילים ומעדכן אותם לבד, אבל גם רושם שרת MCP משלו בשם powerbi-modeling-mcp שרץ דרך npx - כלומר דורש Node ומתנגש בשם עם השרת שרשמת בחלק א׳. בסביבה שלנו, בלי Node, נשארים עם ההעתקה הידנית.

חלק ג׳

עבודה שוטפת - שמור כ‑PBIP

קובץ .pbix הוא ארכיון בינארי סגור. Claude לא יכול לקרוא או לערוך אותו. פורמט .pbip חושף את אותו תוכן כתיקייה של קבצי טקסט - TMDL למודל, PBIR לדוח - וזה מה שהופך את כל השרשרת לאפשרית.

  1. שמור את קובץ ה‑Power BI כ‑PBIP

    ב‑Power BI Desktop: File ← Save as ← בבורר סוג הקובץ בחר Power BI project (*.pbip). שמור אל תוך תיקיית הפרויקט - אותה תיקייה שבה יושבים CLAUDE.md ו‑.claude.

    אם האפשרות לא מופיעה בבורר: File ← Options and settings ← Options ← Preview features, סמן את אפשרות השמירה כ‑‎.pbip‎ ואת אחסון המודל בפורמט TMDL, והפעל מחדש את Desktop.

    התוצאה היא קובץ .pbip קטן לצד תיקיות .SemanticModel ו‑.Report - כולן טקסט קריא.

  2. בקש מ‑Claude להתחבר, ושיאשר לך

    השאר את הקובץ פתוח ב‑Power BI Desktop, פתח את Claude בתיקיית הפרויקט, וכתוב לו בדיוק את זה:

    תתחבר לקובץ <שם הקובץ> שפתוח ב-Power BI Desktop
ותעדכן אותי שהצלחת.

    תשובה תקינה כוללת אישור חיבור עם פרטי המופע המקומי - מזהה תהליך, פורט, ומחרוזת חיבור:

    {
  "success": true,
  "data": [{
    "processId": 27296,
    "port": 55159,
    "connectionString": "Data Source=localhost:55159",
    "parentProcessName": "PBIDesktop",
    "parentWindowTitle": "<your file>"
  }]
}

    אם קיבלת את האישור - הכל מחובר. מכאן זמינות קריאת מטא‑דאטה, יצירת מדדים, שאילתות DAX ועריכת TMDL ו‑PBIR.

    לא קיבלת אישור? חזור לחלק א׳: ודא שה‑JSON עטוף ב‑mcpServers, ושסגרת את Claude סגירה מלאה כולל במנהל המשימות.

  3. אחרי כל שינוי - Apply external changes

    כש‑Claude כותב לקבצים על הדיסק, Power BI Desktop מזהה את השינוי ומציג פס התראה בראש החלון עם הכפתור Apply external changes. לחץ עליו. זהו.

    אל תסגור ואל תפתח מחדש

    סגירה ופתיחה של הקובץ אחרי כל עריכה היא ההרגל שהכי שובר את התהליך: Power BI Desktop מקצה פורט אקראי חדש בכל פתיחה, ולכן החיבור של ה‑MCP נופל וצריך לחבר מחדש בכל סבב. Apply external changes טוען את השינוי בתוך אותו מופע - הפורט נשמר, החיבור חי, ואפשר להמשיך ברצף.

  4. עצור וצלם מסך אחרי כל שינוי

    זהו הפיצוי הישיר על מה שחסר בלי Node. סקיל האימות וסקיל צילום המסך הם שסוגרים בדרך כלל את הלולאה - הם מריצים בדיקת סכימה על הדוח ומחזירים ל‑Claude תמונה של התוצאה, כך שהוא רואה בעצמו מה יצא ומתקן. בלי Node שתי היכולות האלה לא זמינות, ו‑Claude עובד עיוור.

    לכן, למי שלא הצליח להתקין Node - זו שגרת העבודה המומלצת:

    1. Claude מבצע שינוי בקבצים.
    2. לחץ Apply external changes ב‑Desktop.
    3. עצור - צלם מסך של הדוח (Win+Shift+S).
    4. הדבק את הצילום ב‑Claude וכתוב מה לתקן.

    הצילום הידני הוא בדיוק מה שהסקיל היה מספק אוטומטית. עדיף סבב אחד עם תמונה מאשר שלושה סבבים של ניחושים - במיוחד בבדיקת RTL, יישור כותרות ועברית בוויזואלים, שם רק העין תופסת את הבעיה.

מבוסס על התקנה שנבדקה בפועל - Windows, פלטפורמת win32-x64, ללא Node.js וללא הרשאות מנהל.
